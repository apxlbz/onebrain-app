Mint a token, copy one line, then a real cross-agent result. No wizard. Agents: start at For agents or llms.txt.

  1. Sign in at onebrain.apxlbz.com with Google. A personal memory exists immediately.
  2. Open Settings → Connect your tools and press Mint my token. Export it as ONEBRAIN_API_KEY. An agent that already holds your session JWT mints the same token with POST /v1/me/token.
  3. One line per host. Claude Code: 
    curl -fsSL https://onebrain.apxlbz.com/agent-install.sh | ONEBRAIN_API_KEY="$ONEBRAIN_API_KEY" bash -s -- claude-code
    The same script takes cursor, codex, mcp, or rest. Dev is the same command from https://onebrain-dev.apxlbz.com/agent-install.sh. The install page has every line, ready to copy.
  4. Tell one agent something (“remember that launch moved to October 14”), then ask a different agent about it. Same memory, every agent.

What OneBrain is

OneBrain is one long-term memory that every AI agent you use — Claude, ChatGPT, Cursor, your own agents — reads and writes through one standard MCP endpoint. What one agent learns, the others can recall: a preference, a decision, a fact about a project. Every fact keeps the agent that wrote it and when.

Every sign-in gets a private memory of its own, work address or personal: nobody else, not even a coworker on the same domain, can reach a single row. Organizations that set up a shared domain memory before this changed keep it as a shared space; members reach it by adding ?space=<domain> to the connector URL.

OneBrain does not read your Gmail, Calendar, Drive or Trello on its own. Memory comes only from what you and your agents explicitly remember — through a conversation, a hook, or the Memory.md file every connected agent follows.

API reference

Everything the MCP tools do is also plain REST, for agents and scripts that don’t speak MCP. Base URL: 

https://qlpfjeciekaqzribxlnp.supabase.co/functions/v1/api
Every call carries Authorization: Bearer <token> — a personal token (Settings, or POST /v1/me/token from a signed-in session) or a Supabase session JWT. A shared space is selected with ?space=<domain> or an X-OneBrain-Space header; omit both for your personal memory.

The calls below are one real walkthrough, not isolated snippets: a script remembers that a launch date slipped because of a Stripe migration, recalls it back, rates it useful, then forgets it. $BASE and $TOKEN are the base URL and bearer token above; every request and response is exactly what that call sends and gets back.

POST /v1/recall

Search the memory.

ParameterTypeRequiredDescription
querystringYes Search text. Empty, or made only of stopwords (“the”, “what”, …), short-circuits to { results: [], degraded: [] } without spending credit.
limitintegerNo — default 5 Max facts returned, capped at 50 regardless of what is sent.
sourcestringNo Restrict to facts whose input had exactly this source (as recorded by remember, e.g. "zapier").
typestringNo Restrict to one fact type: task, decision, meeting, message, doc, fact, preference, person, handoff.
task_idstringNo Restrict to facts (and handoffs) written with this exact task_id — “what did I/a predecessor learn on task T”.
explainbooleanNo — default false Opt-in ranking diagnostics (also settable via the x-onebrain-explain: 1 request header). When true, every result carries an explain object and the response gains a top-level explain_dropped list — see below. When false or absent the response is unchanged; this never affects which facts are returned or their order.

Request:

curl -X POST "$BASE/v1/recall" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"query": "when is the launch now", "type": "decision", "limit": 5}'

Response — one matching fact, ranked by hybrid semantic + lexical + graph fusion, optionally reranked. content is not the raw text: it is fenced in a <memory_item> tag carrying provenance in its attributes, under the notice every response repeats, so a caller that feeds this straight into a prompt cannot mistake a recalled fact for an instruction. degraded lists which arm(s) failed for this call ("semantic", "lexical", or empty when none did) — fewer or no results from a degraded arm means it had an outage, not that nothing matched. Note: score is whichever search arm's own raw number (a cosine similarity, a lexical ts_rank, or an exact-match 1.0) first produced that result — it is not what decided the returned order (that is RRF fusion plus boosts, then optional rerank) and two results' scores are not comparable. Pass explain: true to see the number that actually decided the order (see this repo's docs/recall-ordering-analysis.md):

      "id": "4b6e6f0e-2c0a-4b2a-9e1f-6c9b7a2d5e10",

      "type": "decision",
      "created_at": "2026-10-12T09:14:31.000Z",
      "score": 0.84,

        "source": "note", "connector": false, "via": "api",

        "agent": { "id": null, "name": "Unknown agent", "kind": "unknown", "label": "Unknown agent", "known": false }
      }

With explain: true, each result additionally carries an explain object, and the response gains a top-level explain_dropped list of up to 10 near-miss candidates that did not make the cut (either the k-slice or a near-duplicate collapse), each with its own per-arm scores so a missing fact can be explained:

        "final_position": 1

    {
      "id": "9a1b2c3d-...",
      "reason": "k_slice",

explain.final_rank_score is the post-fuse number that actually decided the order — unlike score above, it is comparable across results. explain.rerank is null when rerank did not run for this call (disabled, cost-capped, or fewer than 2 candidates). Each result also carries the raw ranking fields (importance, feedback_weight, entity, topic, product, system, tags), omitted above for brevity. framed is every result pre-joined into one block, for a caller that wants to paste the whole batch into a prompt in one piece.

POST /v1/remember

Store a durable fact, preference or decision.

ParameterTypeRequiredDescription
contentstringYes The text to remember, truncated at 500,000 characters. Empty (after trimming) returns 400.
typestringNo A hint from the same vocabulary as recall’s type filter; the extractor may still choose a different one once enrichment finishes.
sourcestringNo — default "note" A label for where this came from. Advisory only: the server always stamps the real caller identity into metadata.provenance itself, so a request can’t write a fact as if another agent said it.
source_refstringNo A per-source idempotency key. Re-sending the same source + source_ref is a no-op ({ stored: false }, nothing new written).
replacesstring[]No Fact ids from a prior recall that this call supersedes (at most 50; anything not a valid uuid is dropped silently rather than failing the write).
task_idstringNo Tag this fact so a successor can filter it back out with /v1/recall’s or /v1/briefing’s task_id.
session_idstringNo Optional, finer-grained than task_id.

Request:

curl -X POST "$BASE/v1/remember" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "content": "The launch moved to October 14 because the Stripe billing migration needs two more days of QA.",
    "type": "decision"
  }'

Response — the fact is stored and already recallable; enrichment: "pending" means the entities, relationships and contradiction check this fact triggers are still running in the background:

{
  "stored": true,
  "raw_id": "8f1c2a90-5e3d-4a7a-b9a6-2d1f5c9e7b44",
  "knowledge_items": 1,
  "facts": [
    {
      "id": "4b6e6f0e-2c0a-4b2a-9e1f-6c9b7a2d5e10",
      "content": "The launch moved to October 14 because the Stripe billing migration needs two more days of QA.",
      "type": "decision"
    }
  ],
  "superseded": [],
  "contradicted": [],
  "enrichment": "pending",
  "agent": { "id": null, "name": "Unknown agent", "kind": "unknown", "label": "Unknown agent", "known": false }

A quick durability check runs before any of this: trivial or one-off chatter (“ok thanks”) is gated and reported, not stored — { "stored": false, "gated": true, "knowledge_items": 0 }, with nothing written and no credit spent.

POST /v1/handoff

Record a handoff for a task: one whole note — unlike /v1/remember, never split into separate facts — so a successor agent recovers your summary, open questions and next steps intact.

ParameterTypeRequiredDescription
task_idstringYes The task this handoff is for. Also tag ordinary /v1/remember writes with the same task_id so /v1/recall can filter to everything learned on that task.
summarystringYes What happened and what you learned. Refused (400), not truncated, past 8,000 characters — split a longer handoff into several calls instead.
session_idstringNo Optional, finer-grained than task_id.
open_questionsstring[]No Unresolved questions for the successor. Refused (400), not truncated, past 20 items or 500 characters per item.
next_stepsstring[]No What to do next. Same 20-item / 500-character-per-item limit as open_questions, refused rather than truncated.

Request:

  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "task_id": "gap-005",
    "summary": "Shipped the handoff primitive: task_id/session_id on remember, recall(task_id=...), and a handoff write.",
    "next_steps": ["Backfill task_id onto older facts if useful"]
  }'

Response:

{
  "stored": true,
  "task_id": "gap-005",
  "fact": { "id": "4b6e6f0e-2c0a-4b2a-9e1f-6c9b7a2d5e10", "content": "…", "type": "handoff" },

POST /v1/feedback

Rate a recalled fact so ranking learns what was useful. Folds into the fact’s feedback_weight with an exponential moving average, so one rating nudges it, several agree it.

ParameterTypeRequiredDescription
fact_idsstring[] (uuid)Yes Ids from a prior recall. Anything that isn’t a uuid is dropped before the update runs.
ratinginteger 1–5No — default 5Clamped into 1–5 if sent outside that range.

Request — the fact from the recall above turned out to be exactly what was needed:

curl -X POST "$BASE/v1/feedback" \

POST /v1/me/token

Mint a personal API token. Needs a signed-in session (a web cookie or an OAuth JWT) — a static token cannot mint another one. Minting again immediately revokes the previous token: one live token per person.

curl -X POST "$BASE/v1/me/token" -H "Authorization: Bearer $SESSION_JWT"
{
  "token": "ob_9fQ2k7mZ4x1R...(rest of a 43-char token)",
  "member": "jordan@acme.com",
  "note": "shown once — minting again replaces this token"
}

Store token immediately and export it as ONEBRAIN_API_KEY. OneBrain keeps only its SHA-256 hash and cannot show it again. A 401 that starts with Mint failed: means the bearer was a static key: retry with ONEBRAIN_SESSION_JWT. The body names the URL.

Architecture

OneBrain runs entirely on Supabase: Postgres with pgvector for storage, Edge Functions (Deno) for every server surface, and GoTrue for auth (Google sign-in, plus MCP OAuth 2.1).

  • Write path (remember). The input is stored verbatim first — immutable, deduplicated by source reference — and is recallable within the same request. In the background, an LLM (DeepSeek, the platform engine) splits it into atomic facts with entities and relationships, embeds them (Qwen3, 1024-d), and a judge retires any fact they contradict.
  • Read path (recall). A query is embedded and matched against the memory with hybrid semantic (pgvector cosine) and lexical (Postgres full text) search, fused and re-ranked by recency, importance, and feedback learned from ratings.
  • Tenancy. Every sign-in gets its own memory (user:<email>), isolated by row-level security keyed off the authenticated caller; domain-shared memories created before this model are kept as opt-in shared spaces.
  • Ingestion. There is currently no automatic ingestion from third-party sources (Gmail, Calendar, Trello, …); every fact comes from an explicit remember call by a connected agent, hook, or the import tool. A background worker (pg_cron, every 30s) only self-heals writes whose enrichment didn’t finish.
  • Billing. Free, Pro, and Team are sized around facts and agents. Free is $0 and holds 500 facts and 2 agents. Pro is $12 a month and Team is $15 per seat per month; both lift those limits. Calling recall and remember is included on every plan. API calls are not metered. The same numbers are on the pricing page.

Deeper design history, including diagrams, lives in the repository’s docs/ directory for anyone with access to the codebase.

Concepts

Namespaces: personal memory vs. shared spaces

Every credential resolves to exactly one namespace (internally an org) — the row-level-security boundary every read and write is scoped to. There are two kinds:

  • Personal (default). Every sign-in’s own namespace, user:<email>, created on first sign-in. Only that person’s own credentials, or agents they connect with a personal token, can ever read or write it — not even a coworker on the same email domain.
  • Shared space. A namespace several members belong to, selected with ?space=<name> on the connector URL or an X-OneBrain-Space header. Only an existing members row grants entry: asking for a space you don’t belong to fails closed (the credential is rejected outright, never silently downgraded to your personal memory). Domain-wide namespaces created before personal-by-default became the model are kept this way; there is currently no self-serve way to create a new shared space.

A credential carries no namespace of its own: a personal token always resolves to its minter’s personal namespace, and a session token resolves to personal unless it asks for a space it belongs to. Many agents (Claude, ChatGPT, Cursor, …) can read and write the same namespace at once — that is the whole point — but one connection only ever reaches one namespace at a time.

Facts, not transcripts

OneBrain does not store conversations. A remember call stores the raw input verbatim first (deduplicated by source reference, immutable and recallable immediately), then an LLM derives it into one or more atomic facts, each carrying a type, the entities and relationships it mentions, and the agent and time that produced it. recall searches facts, never the original input text.

Supersession, not overwrite

Facts are never edited in place. Passing replaces (ids from a prior recall) on a new remember retires the facts it names and links the new fact in their place; a background judge also retires any fact a new one directly contradicts. A retired fact still exists, marked not current, so provenance is never lost — only forget actually deletes anything.

Agent attribution

Every fact keeps which agent wrote it (Claude, ChatGPT, Cursor, a script using a personal token, …) and when, derived server-side from the credential — never from anything the request body claims. The dashboard’s per-fact badge and list_memory’s counts both come from this.

Security

Credentials

Two kinds of bearer credential, both sent as Authorization: Bearer <token>:

  • Personal API token (ob_…), minted at POST /v1/me/token or from Settings. Stored as a SHA-256 hash only — OneBrain cannot show it to you again after the first time. Minting again immediately revokes the previous one (one live token per person). It always resolves to member role, even for the organization’s owner: there is deliberately no way to mint an owner-scoped token, so a leaked hook token can never replace keys, change billing, or delete the organization.
  • Session token — a Supabase-issued JWT from Google sign-in or MCP OAuth, verified against GoTrue on every request (never decoded locally). Carries owner role only when your members row says so; an unconfirmed or anonymous sign-in is rejected outright, since email is the tenancy key.

OAuth (MCP)

Claude, Cursor, VS Code and other MCP clients authenticate with OAuth 2.1: dynamic client registration, PKCE, and a GoTrue-issued access token scoped to the connecting person. OneBrain advertises itself as a protected resource (/.well-known/oauth-protected-resource, RFC 9728) so a compliant client discovers the authorization server on its own. The agent behind an OAuth session is derived from the token’s registered client, never from anything the request claims to be. Claude Code on a fresh login does not see that document until a connect caches it: run claude mcp get onebrain (or /mcp) before claude mcp login. The API-key install above skips this.

Connecting a third-party source (where still offered) likewise uses OAuth at the provider, and requests only read scopes (gmail.readonly, drive.readonly, calendar.readonly, Trello’s read) — OneBrain only reads from sources, never writes or deletes anything at the provider.

Saving data

  • Secrets are stripped on the way in: API keys, passwords and tokens are never written to memory.
  • A quick durability check runs before anything is stored; trivial or one-off chatter is gated and reported back ({ stored: false, gated: true }), not silently kept.
  • Personal tokens are stored hashed; raw inputs, facts and embeddings are isolated per namespace by Postgres row-level security keyed off the authenticated caller, not by application-level filtering alone.

Deleting data

  • forget (the MCP tool, or POST /v1/forget) is a real, irreversible delete — the fact, its embedding, and anything derived from it, not a hidden flag. Delete by ids, or by contains (a text match); a contains match over a safety threshold is refused unless resent with "confirm": true, and "dry_run": true previews a match without deleting anything.
  • A full purge (every input, fact, entity, relationship and summary in the namespace) and organization deletion are owner-only, gated behind re-typing the organization’s exact name, and revoke any connected source’s grant at the provider too — not just locally.
  • GET /v1/export gives back everything as JSON for your own records before deleting anything; embeddings are omitted (reproducible, provider-specific) and forgotten content is left out.

FAQ

Is this a team tool or a personal one?

Personal, by default: every sign-in gets its own private memory. The way in is one token plus one install line. Organizations that already share a domain memory keep it as an opt-in shared space.

Does OneBrain read my Gmail, Calendar or Trello automatically?

No. Automatic ingestion from third-party sources is currently off. Memory is built only from what you and your agents explicitly remember — in conversation, through a hook, or via the import tool.

Can two of my agents see the same memory?

Yes — that is the point. Connect Claude, ChatGPT, Cursor, or any MCP-capable agent with one personal token and one install line; what one remembers, the others can recall.

Can a coworker read my memory?

No, unless you were already part of a shared domain space before the personal-by-default model. A fresh sign-in is always private, even to coworkers on the same email domain.

How do I remove something?

Ask an agent to forget it, call POST /v1/forget, or use the dashboard. Deletion is permanent and cascades to everything derived from that input.

What does it cost?

Free is $0 and holds 500 facts and 2 agents. Pro is $12 a month with unlimited facts and agents. Team is $15 per seat per month. Calling recall and remember is included on every plan. API calls are not metered. The same numbers are on the pricing page.

Can I self-host OneBrain?

Not currently. It runs on a managed Supabase project; there is no self-hosted or on-prem edition.

Is my data used to train models?

No. See Your data and the full Privacy policy.

Troubleshooting

  • ONEBRAIN_API_KEY is required. The shell that ran agent-install.sh did not have the variable. Export ONEBRAIN_API_KEY (or ONEBRAIN_TOKEN, the same key) in that process and re-run. The error prints the mint command for the API it resolved.
  • unknown host. The last argument must be exactly one of claude-code, cursor, codex, mcp, rest. The script exits 2 and reprints the command.
  • HTTP 401, missing or invalid key. Mint on the same project you are calling. Production and dev tokens are not interchangeable. The response body has the mint URL and the install line.
  • Mint failed. POST /v1/me/token was called with the ob_ key. Call it again with the session JWT.
  • “Couldn’t reach the MCP server.” Check the address ends in /functions/v1/mcp with no trailing slash.
  • The sign-in loops. Sign in at onebrain.apxlbz.com first with the same Google account, then connect again.
  • Answers are empty. A fresh memory has nothing in it yet: ask an agent to remember something, or run the import tool, then recall again.
  • A legacy source connection shows “error”. New source connections are not offered under the current model; an existing one can be re-checked from Setup → Sources.
  • Anything else: or@apxlbz.com.
